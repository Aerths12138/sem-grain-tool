# PyInstaller CPU packaging

## Final-change validation

For changes to `ProcessController`, background task lifecycle handling, cancellation,
timeouts, button restoration, or window-close cleanup, run the existing focused test
entry point after the final related edit:

```powershell
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\test_sem_grain_app_frozen.py
```

This focused route covers normal stdout/completion logging, timeout and cancellation
of a process tree, GUI button restoration after timeout, and process-tree cleanup when
the window closes. It also covers manual scale calculation, physical DXF scaling, mask
edit operations, and preservation of the automatic-mask backup. It does not validate
packaged resources or helper outputs.

## GUI correction workflow

1. Select an SEM image and enter the known scale-bar length in micrometers.
2. Use automatic scale detection, or use `人工两点标定` and click both ends of the bar.
3. Run grain detection, then open `人工校正晶粒` when correction is needed.
4. Select one particle to delete, Ctrl-click to select several particles for merging,
   or use the add/split drawing modes followed by `完成绘制`.
5. Save the corrected mask. The original automatic mask is retained once as
   `*_auto_backup.tif`, and the overlay and particle statistics are regenerated.
6. Export circles only after calibration. The GUI converts micrometers per pixel to
   millimeters per pixel for DXF and writes a matching `*_dxf_metadata.json` file.

For a durable record, run the same existing routes through the sequential recorder:

```powershell
# ProcessController and GUI lifecycle changes
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\run_final_validation.py --route lifecycle

# PyInstaller specs, packaged resources, or helper/output behavior changes
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\run_final_validation.py --route packaging

# Run both routes in order
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\run_final_validation.py --route all
```

The recorder does not add another test framework. It invokes the focused test and
packaged acceptance directly and writes relevant final file hashes and modification
times, actual argv, exit status, stdout, covered behavior, and the acceptance artifact
to `dist\SEMGrainTool_final_validation_<timestamp>.json`. It fails if a relevant file
changes during validation, validation starts before the latest related modification,
or packaged acceptance does not return an existing artifact.

Run the complete CPU release build from the workspace root with the bundled CPU Python environment:

```powershell
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\build_cpu_release.py
```

This command runs `check_torch_env.py`, performs a clean PyInstaller build, and then accepts the newly generated product through packaged helper mode. The command fails if any build, resource, helper, or artifact validation fails.

Acceptance covers:

- CPU-only Torch and Cellpose version manifest
- packaged Torch CPU library, CPSAM model, and Tcl/Tk runtime files
- scale-bar JSON generated by `--helper detect_scale_bar.py`
- particle CSV generated by `--helper analyze_particles.py`
- circle preview and circle-only DXF generated by `--helper generate_shapes_from_particles.py`

Every step has a timeout. Its command, process ID, exit code, stdout, stop reason, output paths, and checks are written to one record beside the build:

```text
dist\SEMGrainTool_acceptance_<timestamp>.json
```

Run acceptance without rebuilding an existing product with:

```powershell
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\accept_sem_grain_build.py
```

A controlled missing-resource check is available for validating that acceptance fails and restores the resource afterward:

```powershell
.\SEM_Grain_Tool_Portable\env\python.exe pyinstaller_packaging\accept_sem_grain_build.py --fault-delete-resource tcl_init
```

Build the optional console variant separately with:

```powershell
.\SEM_Grain_Tool_Portable\env\python.exe -m PyInstaller --clean pyinstaller_packaging\SEMGrainToolConsole.spec
```

Outputs:

- GUI application: `dist\SEMGrainTool\SEMGrainTool.exe`
- GUI version manifest: `dist\SEMGrainTool_versions.json`
- Console application: `dist\SEMGrainToolConsole\SEMGrainToolConsole.exe`
- Console version manifest: `dist\SEMGrainToolConsole_versions.json`

Both spec files derive project resources from `SPECPATH`. They require the project-local `SEM_Grain_Tool_Portable\env` interpreter, reject CUDA-enabled Torch before analysis, and collect Tcl/Tk from that same environment. The application is built as `onedir` because Torch, Cellpose, and the bundled model are large.
